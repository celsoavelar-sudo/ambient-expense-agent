# Agent Spec: ambient-expense-agent

## Overview
`ambient-expense-agent` is an event-driven ambient expense processing agent built with the ADK 2.0 Python Graph `Workflow` API (`google.adk.workflow.Workflow`) and enhanced with Agent Runtime deployment scaffolding (`--deployment-target agent_runtime`). It streamlines employee expense reporting by deterministically approving standard low-value claims (`< $100`) in code via an `auto_approve` node while routing higher-value claims (`>= $100`) to a `review_agent` node that summarizes policy considerations with Gemini and pauses execution via `RequestInput` for human-in-the-loop sign-off.

The agent accepts both structured JSON expense events (including via ADK's `/apps/app/trigger/pubsub` ambient trigger endpoint) and plain-text expense prompts (for local CLI smoke testing and evaluation via `agents-cli run` and `agents-cli eval`).

## Language
`python` (ADK Python >= 2.0, scaffolded with `--agent adk_python` and enhanced with `--deployment-target agent_runtime`).

## Architecture & Workflow Graph

### Approaches Considered
1. **Option 1 (Chosen): Hybrid Code-First Triage + Deterministic `auto_approve` + LLM-Assisted `review_agent` with `RequestInput` Pause**
   - Parses structured JSON claims directly in Python (using a lightweight Gemini structured-output extractor only when the input is unstructured plain text), enforces numeric validation and the `$100` threshold strictly in Python code, approves `< $100` claims deterministically in `auto_approve`, and routes `>= $100` claims to `review_agent` for Gemini policy/risk summarization followed by a guaranteed `RequestInput` human-in-the-loop pause and fail-closed resume handling.
   - *Pros*: Deterministic policy enforcement immune to prompt injection, zero LLM latency/cost on structured `< $100` ambient events, guaranteed `RequestInput` pause for `>= $100`, and helpful review summaries for human approvers.
2. **Option 2: Pure Deterministic Python `Workflow` (No LLM Calls)**
   - Uses JSON/regex parsing only and static templates in `review_agent`.
   - *Trade-offs*: Lowest latency, but brittle on free-text claims and provides no contextual risk/policy analysis for human reviewers on large expenses.
3. **Option 3: All-LLM Multi-Agent Graph**
   - Uses `LlmAgent` nodes for intake, routing, `< $100` approvals, and `>= $100` reviews via the `request_input` tool.
   - *Trade-offs*: Adds unnecessary model latency/cost to routine `< $100` claims and risks non-deterministic routing or skipped HITL pauses.

### Graph Topology
- `("START", ingest_expense, {"AUTO_APPROVE": auto_approve, "NEEDS_REVIEW": review_agent, "INVALID": reject_invalid, DEFAULT_ROUTE: reject_invalid})`
  - **`ingest_expense` node**: Parses incoming JSON payload or plain-text expense claim into a typed `ExpenseClaim` Pydantic model (`expense_id`, `employee`, `amount`, `currency`, `category`, `description`, `date`), emitting `"INVALID"` if `amount` is missing or `<= 0`, `"AUTO_APPROVE"` if `0 < amount < 100.0`, and `"NEEDS_REVIEW"` if `amount >= 100.0`.
  - **`auto_approve` node**: Deterministic Python node that approves valid claims under `$100.00`, records the `"approved"` decision in the local in-memory ledger and structured JSON log, and emits both `Event(content=...)` and `Event(output=...)`.
  - **`review_agent` node**: Configured with `@node(name="review_agent", rerun_on_resume=True)` (with `App(..., resumability_config=ResumabilityConfig(is_resumable=True))`). On initial execution, checks company expense policy notes, invokes Gemini (`gemini-3.8-flash`) to produce a concise reviewer brief for the `>= $100.00` claim, emits a structured `expense_review` alert, and yields `RequestInput` to pause for human approval. On resume, reads `ctx.resume_inputs`, fails closed (marks `"approved"` only on explicit `approve`/`yes` confirmation, otherwise `"rejected"`), records the decision in the mock ledger/structured log, and emits the final `Event`.
  - **`reject_invalid` node**: Deterministic Python node that rejects malformed, missing-amount, zero, or negative claims without recording an approval.

## Tools Required
All tools are self-contained local Python functions in `app/tools.py` backed by an in-memory mock ledger and structured JSON logging (no external APIs or credentials required):
- `check_expense_policy(amount: float, category: str) -> dict`
- `emit_expense_alert(submitter: str, amount: float, category: str, risk_summary: str) -> dict`
- `record_expense_decision(expense_id: str, employee: str, amount: float, category: str, description: str, status: str, decided_by: str, reason: str) -> dict`
- `get_expense_ledger() -> dict`

## Constraints & Safety Rules
- **Strict `$100.00` Code Threshold**: Claims with `0 < amount < 100.0` must always route to `auto_approve`. Claims with `amount >= 100.0` (including exact `$100.00`) must always route to `review_agent` and emit `RequestInput`.
- **Prompt-Injection Immunity**: Routing between `auto_approve` and `review_agent` is performed exclusively by deterministic Python numeric comparison on parsed `amount`, never delegated to an LLM router or tool choice.
- **Input Integrity Validation**: Claims missing a parseable numeric amount or with `amount <= 0` (zero, negative, NaN, or infinite values) route to `reject_invalid` and are never approved.
- **Fail-Closed HITL Resume**: When `review_agent` resumes from `RequestInput`, only explicit affirmative responses (normalized `approve`, `approved`, `yes`, `y`) mark the claim `"approved"`; any rejection, empty input, or ambiguous response defaults to `"rejected"`.

## Success Criteria
1. **Auto-Approve Routing (`< $100`)**: `100%` of valid test cases with `0 < amount < 100` execute `auto_approve`, record `status == "approved"`, and emit `0` `RequestInput` interrupts.
2. **HITL Pause & Fail-Closed Resume (`>= $100`)**: `100%` of valid test cases with `amount >= 100` (including `$100.00` boundary and `$500.00` prompt-injection cases) execute `review_agent`, emit `1` `RequestInput` event on initial run, approve on `"approve"` resume, and reject on `"reject"` or ambiguous resume.
3. **Invalid Claim Rejection**: `100%` of missing-amount, `$0`, and negative-amount test cases route to `reject_invalid` with `status == "rejected"`.
4. **Automated Verification & Eval**:
   - `100%` pass rate on `uv run pytest` covering graph node names (`auto_approve`, `review_agent`), `< $100` approval, `>= $100` `RequestInput` pause/resume, invalid claim rejection, and `/apps/app/trigger/pubsub` endpoint execution.
   - `RESULT: PASS` (`custom_response_quality >= 4`, `threshold_policy_compliance == 1.0`) on `agents-cli eval run`.
